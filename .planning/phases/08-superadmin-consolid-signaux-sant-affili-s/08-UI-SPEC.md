# Phase 8 — UI Design Contract

> Visual and interaction contract for the consolidated superadmin back-office (signaux, santé, affiliés/payouts).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> **Coherence mandate:** this phase extends the EXISTING back-office (`(admin)/membres`, `file`, `affiliation`, `affiliation/payouts`). It does NOT introduce a new design language. All new surfaces reuse the established admin page pattern below.

---

## Context Constraints (authoritative — from 08-CONTEXT.md)

- **Internal operator tool** (superadmin only). Prioritize information density + operational clarity over marketing polish.
- **FR mono-language**, fixed copy. Back-office lives at `apps/web/src/app/(admin)` HORS `[locale]` — no i18n routing, no en/ar parity (D-04-03-B). Copy comes from the `admin` namespace in `fr.json`.
- **Gate:** `requireRole('superadmin')` in `(admin)/layout.tsx` → `notFound()` (404) for non-superadmin. New server actions MUST re-validate `requireRole('superadmin')` (defense in depth, T-07-ADMIN-WRITE).
- **Read-only signaux** (D-05): no edit/delete of signals from admin.
- **No auto-alerting** (D-08): health view is visibility only.
- New surfaces: (1) consolidated admin shell with persistent sidebar, (2) `/admin` dashboard landing with KPI cards, (3) `/admin/signaux`, (4) `/admin/sante`, (5) enriched payout workflow.

## Established Admin Page Pattern (MUST match — source of truth)

Observed verbatim in `(admin)/membres/page.tsx` and `(admin)/affiliation/payouts/page.tsx`:

| Element | Contract |
|---------|----------|
| Page container | `<main className="mx-auto max-w-6xl px-4 py-8">` |
| Page title (h1) | `<h1 className="text-2xl font-semibold">` |
| Filter bar | GET `<form className="mt-6 flex flex-wrap items-end gap-3" method="get">`, URL-synced (`searchParams`) |
| Filter field group | `<div className="grid gap-1.5">` + `text-sm text-muted-foreground` label |
| Native select filter | `className="h-9 rounded-md border bg-background px-3 text-sm"` (or shadcn `Select`) |
| Data table | shadcn `Table` inside `<div className="mt-6 w-full overflow-x-auto">` |
| Empty state | `<div className="rounded-lg border border-dashed p-10 text-center">` → `font-medium` heading + `mt-1 text-sm text-muted-foreground` body |
| Money | `<bdi>{formatAtomic(BigInt(...))} {unit}</bdi>` (CR-02: bigint as string, never `Number()`) |
| Date | `Intl.DateTimeFormat('fr-FR', { dateStyle: 'medium' })`, fallback `'—'` |
| Row actions | client island component (`MemberRowActions`, `PayoutRowAction`) using `useTranslations('admin')` + sonner toasts |
| External link | `target="_blank" rel="noopener noreferrer"` (T-07-EXTLINK, anti reverse-tabnabbing) |

**New pages (`/admin`, `/admin/signaux`, `/admin/sante`) MUST reproduce this exact pattern.** RSC `page.tsx` (read repo) + `actions.ts` (mutations under re-guard).

## Admin Shell / Sidebar (D-01, new)

Persistent sidebar mounted by `(admin)/layout.tsx` (or a client component it mounts), under the existing `requireRole('superadmin')` gate.

| Property | Contract |
|----------|----------|
| Layout | Two-column: fixed sidebar (left, logical `inline-start`) + scrollable content. Content keeps its own `max-w-6xl` main. |
| Sidebar width | `w-60` (240px) desktop. |
| Sidebar surface | `bg-card text-card-foreground border-e border-border` (secondary 30% surface). |
| Nav items (order, D-01) | Tableau de bord · Membres · File · Affiliation · Payouts · Signaux · Santé. |
| Nav item idle | `text-muted-foreground` + `rounded-md px-3 py-2 text-sm` |
| Nav item hover | `hover:bg-accent hover:text-accent-foreground` |
| Nav item active | `bg-primary/10 text-primary font-medium` (accent reserved for active route — see Color) |
| Nav item icon | lucide, 16px, leading the label with `gap-2` |
| Active detection | client component reading `usePathname()`; prefix-match for nested routes (e.g. `/admin/affiliation/payouts` highlights Payouts). |
| Mobile | Operator tool, desktop-first. Below `md`: sidebar collapses to a top bar or a `Sheet`-style off-canvas — acceptable to defer to a simple stacked nav; no responsive polish required beyond not breaking. |
| Header strip (optional) | thin top bar with section title; not required if h1 per page suffices. |

Suggested lucide icons: `LayoutDashboard`, `Users`, `Inbox`, `Share2`, `Wallet`, `Radio`, `Activity`.

## Santé View `/admin/sante` (D-06/D-07/D-08, new)

Operational at-a-glance: traffic-light freshness per source + job_runs table. Visibility only (no alerting, D-08).

### Freshness traffic lights (D-06)

Per source (candles / news / macro), based on the existing `stale` threshold logic / `v_data_freshness`.

| State | Semantic | Token | Visual |
|-------|----------|-------|--------|
| Vert | frais (within threshold) | `emerald` | dot `bg-emerald-500` + label « À jour » |
| Orange | limite (approaching stale) | `amber` | dot `bg-amber-500` + label « Limite » |
| Rouge | stale (over threshold) | `red` | dot `bg-red-500` + label « Périmé » |

- Render as a row of source cards or a compact list: each shows source name, colored dot (`size-2.5 rounded-full`), state label, and last-fresh timestamp (`Intl.DateTimeFormat` + relative hint).
- Exact orange-vs-red thresholds derived from existing `stale` job logic (Claude's Discretion, D-06).

### Jobs table (D-07)

shadcn `Table` (established pattern): Job · Statut (ok/échec) · Durée · Dernier run (horodatage).

| Column | Contract |
|--------|----------|
| Statut | Badge: `ok` = `border-emerald-600/30 bg-emerald-500/10 text-emerald-700 dark:text-emerald-400`; `échec` = `border-red-600/30 bg-red-500/10 text-red-700 dark:text-red-400`. |
| Durée | ms/s formatted, `<bdi>`. |
| Dernier run | `Intl.DateTimeFormat('fr-FR', { dateStyle: 'medium', timeStyle: 'short' })`. |
| Empty | dashed-border block. |

## Payout Workflow Enrichment `/admin/affiliation/payouts` (D-09/D-10, extend existing)

Existing page already renders due+paid commissions with amber « À payer » badge and TronScan tx link (Phase 7). Enrichment:

| Property | Contract |
|----------|----------|
| Mark paid action | existing `PayoutRowAction` dialog: collect **tx reference** (manual input, `^[0-9a-fA-F]+$`-ish per existing validation) + amount (USDT → atomic string, CR-02). Server action `payCommission` re-guards `requireRole('superadmin')`, calls atomic RPC `mark_commission_paid` (anti double-payout in DB). |
| History (D-09) | paid commissions remain visible in the same table (status `paid`, secondary badge, tx link to TronScan). No separate history page required; in-app history = the persisted `paid` rows (CSV export deferred). |
| Confirmation | mark-paid is a financial mutation → confirm inside the dialog (explicit « Marquer payé » submit). Idempotent + auditable server-side (M-01..M-05 guarantees reused). |
| Success/error | sonner toast (`useTranslations('admin')`), keyed copy. |

## Spacing Scale

Declared values (multiples of 4), consistent with existing admin pages:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-label gaps (`gap-1`), inline badge padding |
| sm | 8px | Compact spacing (`gap-2`), nav item gap |
| md | 16px | Default element/card gap (`gap-4`, `px-4`) |
| lg | 24px | Section padding |
| xl | 32px | Page vertical rhythm (`py-8`) |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: traffic-light dot `size-2.5` (10px) is a decorative indicator, not a layout unit. Empty-state padding `p-10` (40px) is the established admin convention (`border border-dashed p-10`).

## Color

Tokens LOCKED from Phase 2 (`globals.css`). 60/30/10 mapping:

| Role | Value (light / dark) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `#FFFFFF` / `#0B1220` (`--background`) | Page background, content surface |
| Secondary (30%) | `#F4F6F9` / `#141C2B` (`--card`/`--secondary`) | Sidebar, cards, table header zones |
| Accent (10%) | `#1E5FBF` / `#3B82F6` (`--primary`) | see reserved list below |
| Destructive | `#5B6675` / `#9AA7B8` (`--destructive`, neutral — never red) | neutral destructive emphasis only |

**Accent (`--primary`) reserved for:** active sidebar nav item, primary buttons (e.g. dialog submit « Marquer payé »), focus ring, and links (`text-primary underline`). NOT for badges, NOT for status, NOT for decorative surfaces.

### Status color exception (scoped, deliberate — extends Phase 2 D-04)

Phase 2 reserved green/red for trading widgets only. **Phase 8 adds a scoped operational-status exception** (mandated by D-06/D-07): green/orange/red are permitted EXCLUSIVELY for operational health indicators — never for trading direction, never for marketing.

| Use | Allowed colors |
|-----|----------------|
| Santé freshness dots | `emerald-500` / `amber-500` / `red-500` |
| job_runs status badge | emerald (ok) / red (échec) tinted badges |
| Telegram publication badge | emerald (posté) / red (échoué) / muted `secondary` (non publié) |
| Payout « À payer » badge | amber (existing Phase 7 convention) |
| Trading direction (long/short) | NEUTRAL text only — green/red FORBIDDEN here (D-04 holds) |

Badge tint convention (from existing code): `border-{c}-600/30 bg-{c}-500/10 text-{c}-700 dark:text-{c}-400`.
