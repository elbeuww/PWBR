# Phase 7 — UI Design Contract

> Le design system est **déjà figé en Phase 2** (`02-UI-SPEC` §Color, D-02-01-A→F). Ce contrat documente uniquement ce que P7 ajoute (4 surfaces + grille de paliers + copywriting `affiliate`).

## Spacing Scale

| Token | Value | Usage P7 |
|-------|-------|----------|
| xs | 4px | gap icône/texte, padding inline badge |
| sm | 8px | espacement compact (cellules de table, gap label/input) |
| md | 16px | espacement par défaut entre champs du formulaire, padding de carte |
| lg | 24px | padding de section, gap entre tuiles de métriques |
| xl | 32px | gaps de layout (`py-8` des pages admin existantes = 32px) |
| 2xl | 48px | ruptures de section majeures |
| 3xl | 64px | espacement niveau page |

Exceptions : touch targets des boutons d'action ≥ 44px sur mobile (boutons shadcn `size="default"` = h-9/36px → utiliser `size="lg"` ou `min-h-11` pour les actions tactiles de payout/revue). Sinon : aucune.

| Role | Size | Weight | Line Height | Usage P7 |

Hérité Phase 2 (`02-UI-SPEC` §Color). Palette de marque bleu institutionnel. **Vert/rouge réservés au trading (D-04) — INTERDITS dans les surfaces d'affiliation** (ce ne sont pas des widgets de trading).

| Role | Value (light / dark) | Usage P7 |
|------|----------------------|----------|
| Dominant (60%) | `--background` #FFFFFF / #0B1220 | fond des pages, surface de table |
| Secondary (30%) | `--card`/`--secondary` #F4F6F9 / #141C2B | tuiles de métriques, en-têtes de table, cartes de candidature |
| Accent (10%) | `--primary` #1E5FBF / #3B82F6 | voir liste réservée ci-dessous |
| Destructive | `--destructive` #5B6675 / #9AA7B8 (**gris neutre, jamais rouge** — D-04) | action de rejet de candidature uniquement |

**Accent (`--primary`) réservé à :**
1. Le CTA primaire de chaque surface (bouton « Envoyer ma candidature », « Marquer payé »).
2. La barre de `progress` de progression vers le palier suivant (dashboard).
3. Le badge du palier actuel de l'affilié (`bg-primary/10 text-primary` ou variante `badge`).
4. Les liens (tx_hash → TronScan, miroir `text-primary underline` de la file P4).
5. L'anneau de focus (`--ring`, accessibilité clavier).

**Accent JAMAIS utilisé pour :** lignes de table génériques, fonds de tuile, texte de corps, bordures par défaut.

**Statuts (badges) — palette neutre/ambre, jamais vert/rouge :**

| Statut | Style badge | Surface |
|--------|-------------|---------|

| Candidature `approved` | neutre `text-muted-foreground` + variante `secondary` | 2 |

## Tier Grid & Progression (contrainte clé D-01/D-02/D-14)

La grille des 8 paliers doit être **lisible et statique** (référence pédagogique) ; la progression doit être **immédiate**.

- **Grille 8 paliers** : composant `table` lecture seule, 3 colonnes (Palier · Inscrits via le code · Taux). Palier actuel mis en surbrillance (`bg-primary/10`, badge accent). Valeurs figées de D-01 (8 % → 20 %).
- **Progression vers le palier suivant** : `card` dédiée avec `progress` accent. Libellé = « Palier {n} · {taux}% — {X} inscrits, {Y} avant le palier {n+1} ({taux+1}%) ». Au palier 8 (max 20 %) : pas de barre, message « Palier maximum atteint ».
- **Découplage audience/argent (D-02)** affiché explicitement : tuile « Inscrits via le code » (détermine le taux) **distincte** de la tuile « Abonnés actifs ramenés » (détermine le montant). Un libellé court (`tooltip`) rappelle que le taux suit l'audience, le montant l'argent réel encaissé.

**Tuiles de métriques (D-14, set complet) — `card`, agrégats seuls :**
1. Palier & taux actuel (badge accent)
2. Inscrits via le code (total)
3. Abonnés actifs ramenés (en cours)
4. Revenus générés — `tabs` cumul / mois courant (`<bdi>` + `formatAtomic`)
5. Commissions dues (ambre)
6. Commissions payées (neutre)

**No-PII strict (D-13) :** AUCUNE ligne par filleul, AUCUN identifiant filleul, AUCUNE date d'inscription individuelle. Le checker et l'auditeur DOIVENT échouer si une surface affilié rend une boucle/table sur des referrals individuels.

## Copywriting Contract

Namespace i18n **nouveau** : `affiliate` (trilingue FR/EN/AR à parité STRICTE de clés, check CI existant). Le back-office (surfaces 2 et 4) est **mono-FR** (étend `admin`, hors `[locale]`, invariant D-04-03-B). Copy FR = source canonique ci-dessous. Ton éducatif, **aucune promesse de gain** (LEGAL-01, garde no-perf-claims VITR-03).

| Element | Copy (FR canonique) |
|---------|---------------------|
| CTA candidature (surface 1) | **« Envoyer ma candidature »** |
| CTA payout (surface 4) | **« Marquer comme payé »** |
| Empty state heading — file de revue vide (surface 2) | « Aucune candidature en attente » |
| Empty state body — file vide | « Les nouvelles candidatures d'affiliés apparaîtront ici pour revue. » |
| Empty state heading — dashboard sans données (surface 3) | « Pas encore de filleuls » |
| Empty state body — dashboard sans données | « Partagez votre code d'affiliation pour commencer à parrainer. Vos statistiques s'afficheront ici dès la première inscription. » |
| Empty state — payouts (surface 4) | « Aucune commission à payer pour le moment. » |
| Error state — soumission candidature échouée | « Échec de l'envoi de la candidature. Vérifiez votre connexion et réessayez. » |
| Error state — code vanity déjà pris (validation superadmin) | « Ce code est déjà utilisé. Choisissez-en un autre (A-Z, 0-9). » |
| Error state — chargement dashboard échoué | « Impossible de charger vos statistiques. Réessayez dans un instant. » |
| Disclaimer (surfaces 1 et 3) | Réutilise le `<Disclaimer>` RSC P2 (`disclaimer.footer`) : contenu éducatif, aucune promesse de gain. **Sur la page candidature : aucune promesse de revenu d'affiliation.** |

**Actions destructives :**

| Action | Surface | Confirmation |
|--------|---------|--------------|
| Rejeter une candidature | 2 | `alert-dialog` — **motif de rejet requis** (textarea), miroir `rejectDialog` P4. Bouton confirm en `destructive` (gris neutre). |
| Marquer une commission payée | 4 | `alert-dialog` — saisie **tx_hash + montant + date** obligatoires (D-15), confirmation avant écriture `service_role`. Action **irréversible** côté UI → confirmation explicite. Bouton confirm en `primary` (action positive, pas destructive). |

**Sous-namespaces `affiliate` suggérés (parité 3 langues) :** `application.*` (form labels: réseaux sociaux, Telegram, Facebook, nb abonnés, interactions ; submit ; success ; errors), `dashboard.*` (metrics, tiers, progress, empty, errors), `tiers.*` (grille). Sous-clés `admin` mono-FR : `affiliateQueue.*`, `payouts.*`.

## Interaction Contracts

| Contrat | Détail |
|---------|--------|
| Formulaire candidature | Validation client zod + serveur (react-hook-form, pattern P4). Champs requis : ≥1 réseau social, nb abonnés (entier ≥0). Toast `sonner` succès → état « candidature reçue ». Anti double-submit (bouton `disabled` pendant pending). |
| File de revue | Actions Approuver / Rejeter (motif) via server action `service_role` (`QueueRowActions`-like). Approuver → ouvre saisie du code vanity (input borné A-Z0-9). `revalidatePath` après action. |
| Dashboard affilié | Lecture seule, `@tanstack/react-query` (cache + états loading via `skeleton`). Polling/realtime non requis (cadence mensuelle du job). Isolation RLS prouvée (un affilié ne voit jamais un autre). |
| Payout | `alert-dialog` saisie tx_hash/montant/date → server action `service_role` insère `payouts`, transition commission due→payée. Lien tx_hash → TronScan (`target="_blank" rel="noopener noreferrer"`, anti reverse-tabnabbing T-04-EXTLINK). |
| RTL | Toutes les surfaces `[locale]` (1, 3) en propriétés logiques Tailwind v4. Montants/%/codes/tx_hash en `<bdi>`. Aucune classe directionnelle en dur (`ml-`/`pl-` → `ms-`/`ps-`). |
| Accessibilité | Focus ring `--ring` accent. `progress` avec `aria-valuenow`/`aria-valuemax`. Boutons d'action avec label texte (pas icône seule). Contraste hérité palette P2 (validé). |
