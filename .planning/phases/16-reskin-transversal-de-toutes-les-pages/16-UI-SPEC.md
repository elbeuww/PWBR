# Phase 16 — UI Design Contract

> Visual and interaction contract for the **transversal reskin** of every existing surface onto the frozen DS v3 dark néon (Phase 15). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope: repaint vitrine (accueil/tarifs/méthodologie/légal), auth (login/signup), compte/abonnement, espace membre (liste signaux + détail trade + chart), paiement/funnel, Académie (index/article/cours-leçon), back-office `/admin` — **single pass**, **no new product capability**.
> **Inheritance:** the design tokens, color, typography, spacing, and theme contract are FROZEN by `15-UI-SPEC.md` (source of truth). This spec adds only the **per-tier neon intensity contract** and the **reskin definition-of-done**, sourced from `16-CONTEXT.md` (D-01..D-14).

**Reskin rule (THEME-02 preserved, D-08):** every reskinned surface references the **component token layer via `var()` only** — zero color literal, zero bespoke per-page CSS. Reskin = swap to DS v3 tokens + apply tier accent primitives. It NEVER migrates the RLS fetch to the client (D-12, Anti-Pattern 3) and NEVER introduces service_role on pages.

| lg | 24px | Section padding |

## Typography

Inherited verbatim from Phase 15. UI text = **Space Grotesk** (`--font-sans`) at **2 weights (400 + 600)**. Display = **Archivo** (`--font-display`), separate family, titles/wordmark only.

| Role | Family | Size | Weight | Line Height |
|------|--------|------|--------|-------------|
| Body | Space Grotesk (`--font-sans`) | 16px | 400 (regular) | 1.5 |
| Label / meta | Space Grotesk (`--font-sans`) | 14px | 600 (semibold) | 1.4 |
| Heading | Space Grotesk (`--font-sans`) | 20px | 600 (semibold) | 1.2 |
| Display | Archivo (`--font-display`, distinct family) | 28px+ (clamp on landing) | `--display-weight: 800` (faux-bold over Archivo 600) | 1.0–1.2 |
| Numeric / tabular trading | JetBrains Mono (`--font-mono`) | inherits row size | 400/600 | 1.4 |
| Arabic (`:lang(ar)`) | Noto Sans Arabic | inherits | 400/600 | 1.6 (diacritics) |

> **Weight scope (checker FLAG, D4 clarification):** the two operational UI weights are **400 + 600** (Space Grotesk, JetBrains Mono, Noto Sans Arabic). `--display-weight: 800` applies **exclusively to Archivo** (isolated display family — titles/wordmark only) and is **never** used on Space Grotesk or body/UI text. The system is therefore 2 operational weights + 1 display-only weight on a distinct family, not a 3-weight UI scale.

Rules (tier-aware, D-07):
- **Gradient-green titles are landing-only.** App-tier headings (Tier 2/3) use **flat tokens** (`text-foreground` / `text-primary` accent), never the gradient title treatment.
- Display uppercase + tracking is `.nxl`-scoped; platform headings stay sentence-case unless a vitrine surface opts into the display treatment.

## Color

Single frozen theme = **GREEN** (`:root`, THEME-03). Values promoted verbatim from `.nxl[data-theme="green"]`. Verified contrast: primary/bg 11.39:1, text/bg 18.93:1, muted/bg 6.76:1 — all WCAG AA+ (THEME-05).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#070b08` (bg) / `#0b110d` (bg2) | Page background, app shell, band backgrounds |
| Secondary (30%) | `#0f1611` (surface-solid) + `rgba(255,255,255,0.035)` (translucent) | Cards, popovers, nav, sidebar, dialogs, table rows |
| Accent (10%) | `oklch(0.84 0.18 150)` cyber green (`--primary`) | See reserved-for list below |
| Destructive | `oklch(0.68 0.2 24)` (`--destructive` / `--nexa-signal-bear`) | Destructive actions only |

Supporting tokens (frozen `:root`, do not re-declare):

| Token | Value | Role |
|-------|-------|------|
| `--foreground` | `#eafff1` | Primary text |
| `--muted-foreground` | `rgba(212,244,224,0.64)` | Secondary text |
| muted/disabled | `rgba(212,244,224,0.40)` | Tertiary / placeholder |
| `--border` | `rgba(255,255,255,0.10)` | Borders, dividers |
| `--primary-foreground` | `#051009` | Ink ON green primary |
| `--glow` | `oklch(0.84 0.18 150 / 0.55)` | Box-shadow glow on primary surfaces ONLY |
| `--signal-bullish` | `oklch(0.82 0.18 150)` (buy) | Trading direction — bull (distinct from `--primary`, D-11) |
| `--signal-bearish` | `oklch(0.68 0.2 24)` (sell) | Trading direction — bear |
| risk/warn | `oklch(0.82 0.15 80)` amber | Moderate-risk ScoreRing only |

**Accent reserved for (explicit — never "all interactive elements"):**
- Primary CTA buttons (`Button variant=default` → `bg-primary text-primary-foreground`)
- Focus rings (`--ring` = primary green; never legacy `ring-[#2563EB]`)
- Active state of segmented controls (LanguageSwitcher active item)
- Eyebrow text + dot, section eyebrows (vitrine), `.accent` links/checkmarks in pricing lists
- "Popular" price card border + glow, price badges
- Discreet card/CTA glow on Tier 2 app surfaces (per tier model below)
- Hero aura / globe / gradient titles / data-rain — **vitrine (Tier 1) only**, color-mix derived, opacity-capped

**CandleChart color contract (D-11 — carry-forward, do NOT re-decide):**
- Recolored via the **lightweight-charts JS API** (lwc does not read CSS vars — Anti-Pattern 5), never bespoke CSS.
- Candle up/down via the **`--signal-bullish` / `--signal-bearish`** namespace — **distinct from `--primary`** (green ≠ direction).
- Score = ring; color = **risk** (never green=winner).

**Color guardrails (THEME-02 scan targets — must stay green this phase):**
- No hardcoded `ring-[#2563EB]` anywhere (route to `ring-ring`).
- No raw palette utilities (`text-amber-700`, `text-emerald-400`, `bg-red-500/10`, `border-emerald-600/30`…) in admin/affiliation/track-record — route through semantic tokens (`text-destructive`, `text-[--signal-bullish]`, `bg-muted`…). These are the "CSS bespoke par page" the scan must prove absent (D-09 condition 1).
- `ring`/glow collision: glow is `box-shadow`, never a Tailwind `ring-*` utility — keep distinct so `focus-visible:ring-*` does not double-render against brand glow.

**Translucent-surface AA (THEME-05):** glow cards / overlays / backdrop-blur nav use `rgba(...,0.035)` / `color-mix` — contrast measured against the **composited** `#070b08` base, not the translucent layer alone.

## Neon Intensity Tiers (phase-specific — D-04, D-05, D-06, D-07)

The defining contract of this phase. Every surface MUST declare its tier; the verifier checks the tier accent is applied (D-09 condition 2 — a page "only tokenized but fade" does NOT pass).

| Tier | Surfaces | Neon treatment | Forbidden |
|------|----------|----------------|-----------|
| **Tier 1 — Vitrine (full neon)** | accueil/landing, tarifs, méthodologie, légal | Glow, gradients, aura/halo, data-rain, gradient titles — rich showcase | — |
| **Tier 2 — App (intermediate)** | espace membre (liste signaux + détail + chart), compte/abonnement, auth (login/signup), paiement/funnel, Académie | Neon accents + **discreet glow on cards/CTA/focus**. **Readability first** on dense surfaces | No section aura/halo, no gradient titles, no heavy data-rain |
| **Tier 3 — Admin (sober)** | `/admin` (all routes) | DS v3 tokens + components + **minimal neon borders**, zero effect | No hero, no animation, no glow effects (Phase 11 D-18, do NOT re-decide) |

**Transversal neon primitives (D-06 — tokenized, reusable on Tier 2):**
- **Card/CTA/focus glow** — discreet neon halo via `--glow` (`box-shadow`), on cards, primary buttons, focus states. `var()` only, no bespoke literal (D-08).
- **Data-rain** — promoted to a **light primitive**, applied **ambient + very subtle ONLY** on **calm surfaces** (auth, empty states, member overview header). **NEVER** on signal lists / tables / trade detail (D-05/D-07).

**Landing-only primitives (D-07 — NOT generalized):**
- **Gradient-green titles** (app titles = flat tokens).
- **Section aura/halo** (vitrine headers only).

**Dense-data readability rule (D-05):** signal list, trade detail, admin tables prioritize legibility — no heavy neon effect that parasitizes reading.

**Reduced motion (D-14, carry-forward):** `prefers-reduced-motion` ⇒ static composition (no animation, visual composition preserved) — applies to every neon primitive added (glow, data-rain).

## Reskin Definition of Done (D-09, D-10 — verifier grid, not subjective review)

A surface is "reskinned DS v3" when, **per surface**, all 4 are true:

1. **Zero bespoke CSS / zero color literal** — DS v3 component-layer tokens only (`var()`).
2. **Tier accent applied** — glow/gradient/effects per the surface's tier (D-04). Tokenized-but-fade does NOT suffice.
3. **Guard scans green** — `no-perf-claims` + `no-mera-brand`.
4. **Guardrails preserved** — RLS gating (fetch never migrated to client, D-12), RTL logical properties, `<Disclaimer />`, `data-testid` / ARIA roles unchanged (E2E Phase 21).

## Copywriting Contract

This phase ships **no new product screens** — it repaints existing surfaces. Existing copy (CTA labels, empty states, error states, destructive confirmations) is **inherited unchanged**; only the visual treatment routes to DS v3 tokens. All strings stay trilingual (fr/en/ar, strict key parity). FR canonical. No hardcoded text introduced by the reskin (i18n scan `lint:i18n`).

| Element | Copy |
|---------|------|
| Primary CTA | Inherited, unchanged — FR « Commencer » / EN "Get started" / AR «ابدأ» (vitrine), funnel CTAs unchanged. Rendered via `--primary` GREEN. No new label introduced |
| Empty state heading | Inherited per surface (member signals empty, admin tables empty) — unchanged. Reskin only restyles; may add subtle data-rain ambient (Tier 2, calm surface) |
| Empty state body | Inherited — do NOT invent new copy. Existing member/admin empty states keep their text + next-step |
| Error state | Inherited per surface. `% ` rendering still routed via `applyThreshold` + N + provenance (D-13, VITR-03) — no naked %, no gain promise |
| Destructive confirmation | Inherited flows (e.g. cancel-subscription, payout) keep existing copy; only color routes to `--destructive`. **No new destructive action introduced this phase** |

**Guardrail copy scans (D-09 condition 3):** `no-perf-claims` (every % measured, with N + provenance, no gain baseline) and `no-mera-brand` (no "MERA" / "Make Everybody Rich Again") must stay green on every reskinned surface.
