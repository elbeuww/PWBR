# Phase 10 — UI Design Contract

> Visual and interaction contract for the NEXA design-system foundation. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Phase nature: foundation / tokens, not screens.** This phase ships *values and plumbing* (OKLCH token layers, 5 self-hosted fonts, no-flash theme, RTL-safe base) — NOT components, layout, or copy-bearing surfaces (those are Phase 11). ## Token Architecture (DESIGN-01)

Three layers, all in `globals.css` (Tailwind v4 CSS-first). Phase 11 consumes **semantic + component** names only — never raw primitives.

| Layer | Where | Role |
|-------|-------|------|
| **Primitive** | `@theme` / `:root` (raw OKLCH ramps) | NEXA palette ramps + neutral ramp. Never consumed directly by components. |
| **Semantic** | `:root` / `.dark` (`--primary`, `--background`, `--ring`…) | Maps to primitives. Flips light↔dark. The only layer that changes per theme. |
| **Component** | `@theme inline` (`--color-*`, `--radius-*`) | Maps shadcn token names to semantic vars. Consumed by `bg-primary`, `text-foreground`, etc. |

Rule: the **semantic token names stay identical to v2.0** (`--primary`, `--accent`, `--ring`, `--card`…). The NEXA switch = new primitive ramp + re-pointed values, **not** renamed tokens — so the 20 existing `ui/` components reskin automatically (CONTEXT §Reusable Assets).

## Spacing Scale

8-point scale, inherited from Tailwind v4 defaults (already in use across v2.0). Phase 10 does **not** introduce custom spacing tokens.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: none. Touch targets (44px min) handled at component level in Phase 11.

**RTL note (DESIGN-04):** all spacing applied via **logical properties only** (`ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`) — never `ml-/mr-/left-/right-`. This convention is already established (CONTEXT §Established Patterns) and must be preserved in any base-layer rule this phase touches.

## Typography (DESIGN-02)

5 self-hosted families via `next/font/local`, each exposed as a CSS var. Inter (`next/font/google`) and IBM Plex Sans Arabic **removed** (D-01, D-03). Zero runtime CDN call.

### Family → role mapping (D-02)

| Family | CSS var | Role |
|--------|---------|------|
| **Archivo** | `--font-display` | Display / titles / wordmark (H1–H2, brand) |
| **Space Grotesk** | `--font-sans` | Body / UI — running text, labels, buttons (`body` `font-family` repoints here) |
| **JetBrains Mono** | `--font-mono` | Numeric / tabular data — price, SL/TP, R:R, score /100 |
| **Chakra Petch** | `--font-accent` | Technical accents — badges, cyber labels, stats |
| **Noto Sans Arabic** | `--font-arabic` | Arabic script (applied via `:lang(ar)`), replaces IBM Plex (D-01) |

### Type scale (consumed by Phase 11)

| Role | Size | Weight | Line Height | Family |
|------|------|--------|-------------|--------|
| Body | 16px | 400 (regular) | 1.5 | Space Grotesk |
| Label | 14px | 600 (semibold) | 1.4 | Space Grotesk / Chakra Petch (accents) |
| Heading | 20px | 600 (semibold) | 1.2 | Archivo |
| Display | 28px | 600 (semibold) | 1.2 | Archivo |

Weights: 2 only — **regular (400)** + **semibold (600)**. Per-family self-hosted weights are Claude's-discretion (bundle vs hierarchy), but the rendered scale must stay at these 2 weights.

**Arabic:** `:lang(ar)` keeps generous `line-height: 1.6` for diacritics (CONTEXT §Established Patterns). RTL comes from `<html dir="rtl">` + logical props, not from the font.

## Color (DESIGN-01, D-04 / D-05)

NEXA palette switches **in Phase 10** (success criterion #2). Brand exits the v2.0 institutional blue `#1E5FBF`. All values declared in OKLCH (HEX→OKLCH conversion is Claude's-discretion; values below computed and locked here).

### Brand primitives

| Name | HEX (source) | OKLCH | Role |
|------|------|-------|------|
| Cyber green | `#03d87f` | `oklch(0.7754 0.1896 155.45)` | Brand / primary accent — CTA, focus ring, active states |
| Royal purple | `#63279b` | `oklch(0.4233 0.1772 302.98)` | Secondary brand accent — eyebrows, gradients, technical highlights |

### Semantic roles (60/30/10)

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `oklch(1.0000 0 0)` (`#FFFFFF`) | `oklch(0.1663 0.0262 269.37)` (`#0a0e1a` near-black navy) | `--background`, page surfaces |
| Secondary (30%) | neutral surface (light card) | dark slate navy | `--card`, `--secondary`, `--muted`, header/footer/nav |
| Accent (10%) | `oklch(0.7754 0.1896 155.45)` cyber green | brightened green for dark-contrast | `--primary`, `--ring` — see reserved list |
| Destructive | `oklch(0.5771 0.2152 27.33)` (`#dc2626`) | same hue, dark-tuned | Destructive UI actions only (NOT bearish trading) |

**Accent reserved for (explicit — never "all interactive elements"):**
- Primary CTA buttons (`--primary`)
- Focus rings (`--ring`)
- Active nav / selected state indicators
- Brand wordmark / eyebrow accents (royal purple variant)

Everything else (links, secondary buttons, borders) uses neutral/secondary tokens, not the brand accent.

### Trading-signal tokens — SEPARATE namespace (D-05, hard rule)

The brand cyber green **must never** encode trade direction. Bullish/bearish are distinct tokens at distinct hues/usages, documented in the token layer for Phase 11+:

| Signal token | OKLCH | Note |
|--------------|-------|------|
| `--signal-bullish` | `oklch(0.6271 0.1699 149.21)` (`#16a34a`, sober green) | Win / long — **sober**, distinct from vivid brand green `oklch(0.7754 …)` |
| `--signal-bearish` | `oklch(0.5771 0.2152 27.33)` (`#dc2626`, red) | Loss / short |

Brand green (`oklch(0.7754 …)`, vivid, hue 155) vs bullish green (`oklch(0.6271 …)`, sober, hue 149) are visually and semantically separable. This separation **must be documented in the token CSS** (D-05) so Phase 11 never collapses them.

**`--destructive` status (Claude's discretion, resolved):** promoted from v2.0 neutral grey to a real red (`oklch(0.5771 0.2152 27.33)`), now that trading reds live in their own `--signal-bearish` token. Destructive = irreversible UI actions (delete, cancel); bearish = trade outcome. Two tokens, never shared.
