# Phase 4 — UI Design Contract

> Visual and interaction contract for the **encashment milestone**: the USDT TRC-20 payment MVP and subscription lifecycle. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Surfaces covered (8 requirements PAY-01..06, ADMIN-01/02):**
> 1. **Plan/pricing selection** — standard 9 $/mois + découverte 3 $/7 j one-shot (PAY-06). Replaces the P2 "paiement bientôt" placeholder.
> 2. **Payment submission** — USDT TRC-20 receive address (network in large + QR + 1-tap copy) + exact amount due with unique offset + tx-hash field + optional screenshot (PAY-01, PAY-02, D-01/D-03/D-05).
> 3. **Live on-chain verification** — polling "Vérification en cours…" with steps; access opens on confirmation (PAY-02/PAY-03, D-02).
> 4. **Verification failure** — precise reason + traced re-submission (PAY-04, D-04).
> 5. **Subscription status / expiry banner** — in-app J-3/J-1 reminder, hard cut at period end, NO email (PAY-05, D-09/D-10).
> 6. **Superadmin members admin** — list (status/email/plan/expiry/last-payment + actions) + ambiguous-payment validation queue (ADMIN-01/ADMIN-02, D-08/D-13/D-14).
>
> **Inherits the Phase 2 brand contract AND the Phase 3 additions in full** (`02-UI-SPEC.md`, `03-UI-SPEC.md`, live tokens in `apps/web/src/styles/globals.css`). This spec ADDS only what payment + admin need: financial-display rules for atomic amounts, the crypto-novice-reassuring waiting/error language, money-state semantic mapping, table/queue anatomy, and copy/toast feedback. Where P2/P3 fixed a value (spacing, type scale, brand tokens, fonts, icon lib, green/red reservation), it is reused verbatim — not re-decided.
>
> **Brand law (D-01 P2):** serious, credible institutional finance. Sober, anti-scam. No neon, no decorative gradients. Target = non-technical MENA / crypto-novice audience → reassurance and clarity first. This is the "tout l'argent" phase: trust signals over flourish.
> **RTL is first-class:** every component uses CSS logical properties (`ms`/`me`/`ps`/`pe`/`start`/`end`), never `left`/`right`. Validated in `dir=rtl` (ar), both themes. The wallet address, tx-hash, QR and ALL monetary amounts are intrinsically LTR → wrapped in `<bdi>` (anti-inversion, I18N-02).
> **Money-display law (D-V2-03):** amounts are atomic BigInt ×10⁶, zero float. The UI displays the **exact amount due = nominal + unique offset** (e.g. `9.02 USDT`, `3.01 USDT`, D-05). Formatting via `Intl.NumberFormat` (6-decimal capable), always inside `<bdi>`. The displayed amount must match the atomic value byte-for-byte semantically — never round for display in a way that hides the offset.
> **Security-surface law (D-01/D-15):** the single shared receive address is read-only chrome; **no private key, seed, or wallet secret ever appears in UI, props, message files, or client bundle.** The admin surface lives in the `(admin)` route group OUTSIDE `[locale]` (404 for non-superadmin, P1 D-09) and is mono-language (FR).
> **Producer-boundary law (D-08):** the front (anon-client) may only INSERT `payments(pending)` and READ scoped rows. Every transition (`verified`/`active`/`expired`/`rejected`) and every `subscriptions` write goes through `service_role` (server action / route handler / job). Never import the service-role client in `apps/web` client code.
> **Legal gate law (LEGAL-02):** the real production encashment path consumes `LEGAL_REVIEW_DONE` before authorizing a live payment. UI shows the normal flow in dev/test; the gate blocks prod, not the screens.

## Spacing Scale

Inherited from Phase 2/3 (Tailwind v4 default 4px scale). Multiples of 4 only — no new values.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, badge gaps, copy-button affix |
| sm | 8px | Compact stacks, chip padding, table cell vertical rhythm |
| md | 16px | Default element spacing, card inner padding, form field gap |
| lg | 24px | Card padding, gap between plan cards, payment-block sections, admin panel padding |
| xl | 32px | Section breaks (amount block ↔ hash form ↔ screenshot), page section rhythm |
| 2xl | 48px | Major page-section breaks on mobile (e.g. plan choice ↔ payment) |
| 3xl | 64px | Page top/bottom padding on desktop |

Exceptions:
- **Touch targets:** every interactive control (plan-select button, copy-address button, copy-amount button, QR, submit, screenshot picker, retry, admin row actions, tabs) ≥ 44px tappable. RTL-aware. The 1-tap copy buttons are the highest-frequency targets on the most critical screen → never below 44px.
- **Plan cards grid:** 1 column < `md`, 2 columns `md`+ (only two plans). Gap `lg`. Container `max-w-screen-md` centered.
- **Payment panel:** single-column, `max-w-screen-sm`, generous vertical rhythm (`xl` between blocks) — reduce cognitive load on a first crypto payment.
- **Admin tables:** full-width within `(admin)` shell, `max-w-screen-xl`; horizontal scroll wrapper on mobile (tables are dense, mono-language, desktop-first but must not break narrow screens).
- **QR block:** fixed QR size ~ 180–220px, centered, padding `lg` on a `--card` surface with high-contrast quiet zone.

## Typography

Inherited from Phase 2/3: exactly **4 sizes, 2 weights** (Regular 400 + Semibold 600). Body line-height 1.5; heading 1.2/1.25; Arabic +0.1 via `:lang(ar)`. Do NOT introduce a 5th size or 3rd weight.

| Role | Size | Weight | Line Height | Phase-4 usage |
|------|------|--------|-------------|---------------|
| Body | 16px | 400 | 1.5 | instructions, reassurance copy, error/empty copy, table cell text, disclaimer |
| Label | 14px | 600 | 1.4 | field labels, plan meta, table column headers, status badges, step labels, glossary terms |
| Heading | 24px | 600 | 1.25 | page titles ("Choisir une offre", "Payer en USDT", "Vérification en cours…"), admin panel titles |
| Display | 40px | 600 | 1.15 | the **exact amount due** on the payment screen (the single most important number) + plan price on plan cards. Tabular figures, `<bdi>`. |

Mono-spacing rule for technical strings:
- **Wallet address** and **tx-hash** are long opaque strings → render with **tabular Inter** in a visually distinct block (`--card` surface, `--radius-md`, slightly smaller Body or Label size, `break-all`/`overflow-wrap` so they wrap safely, `<bdi>` LTR). A true monospace font is NOT added (no 3rd font); tabular Inter + the boxed treatment is sufficient and stays on-brand.
- **Amounts** (`9.02 USDT`, `3.01 USDT`) always tabular figures, `<bdi>`, currency unit "USDT" as a Label-weight suffix, network "TRC-20" shown prominently near the address (D-01 "réseau en grand").

## Color

Inherits the institutional-blue 60/30/10 brand split (P2) and the trading-semantic green/red reservation (P3). Phase 4 **introduces money/payment STATE colors** — and here, for the first time in the product, **`--destructive` is actually used (red) for genuinely destructive admin actions.**

| Role | Value (light / dark) | Usage |
|------|----------------------|-------|
| Dominant (60%) | `#FFFFFF` / `#0B1220` | Page background, payment panel surface |
| Secondary (30%) | `#F4F6F9` / `#141C2B` | Plan cards, address/QR block, hash form, admin panels, table chrome |
| Accent (10%) — brand blue | `#1E5FBF` / `#3B82F6` | Primary CTA ("Choisir cette offre" / "J'ai payé — vérifier"), the **exact amount emphasis**, active tab, focus ring, copy-button hover, polling spinner/progress fill |
| Destructive (red) | `--destructive` — **set to a real red this phase** (light `#B91C1C` / dark `#EF4444`) | **Genuinely destructive admin actions only:** "Révoquer / Suspendre", "Rejeter" (queue), and their confirmation dialogs. First product use of destructive-red. |

**Money / verification STATE colors (semantic, NOT in the 10% accent budget — used sparingly to encode payment outcome):**

| State | Color (light / dark) | Encodes |
|-------|----------------------|---------|
| En attente / vérification | brand-blue `#1E5FBF` / `#3B82F6` + `Loader2` | "Vérification en cours…", `payments(pending)`, subscription `pending` |
| Succès / actif | green `#15803D` / `#22C55E` (the P3 trading-green, REUSED) | payment verified, subscription `active`, "Paiement confirmé ✓", member status "Actif" badge |
| Échec / rejeté | red `#B91C1C` / `#EF4444` | verification failure callout, `payments(rejected)`, member status "Expiré"/"Suspendu" |
| Ambigu / à valider | amber `#B45309` / `#F59E0B` (NEW, this phase) | over/under-payment in the admin queue, "À valider" badge, expiry-soon warning banner (J-3/J-1) |

> **Amber is the only new hue introduced.** It is reserved EXCLUSIVELY for the "needs human attention / warning" state (ambiguous payment queue rows, expiry-soon banner). It is never decorative and never used on the success/failure paths. Green/red keep their P3 meaning (here extended to payment success/failure status, which is a legitimate result semantic, consistent with "green = good outcome, red = bad outcome"). Color is ALWAYS paired with a text label and/or icon — never the sole signal (colorblind-safe, WCAG).

Supporting tokens (not in accent budget): Text primary `#0B1220`/`#E6EBF2`; Text muted `#5B6675`/`#9AA7B8`; Border `#E2E7EE`/`#26303F`.

**Accent (brand-blue) reserved for (explicit, never "all interactive elements"):**
1. The primary CTA on each screen (plan select, "J'ai payé — vérifier", "Renouveler", admin primary "Activer").
2. The **exact amount due** emphasis on the payment screen (Display size, brand-blue).
3. Keyboard focus ring (`:focus-visible`) on every interactive element.
4. Active admin tab + active selected plan card border.
5. The polling progress fill / spinner accent.

Everything else (labels, borders, table grid lines, copy buttons at rest) uses neutral text/border tokens. Status semantics use the money-state colors above, always with text. Contrast: all pairs meet WCAG AA (4.5:1 body, 3:1 large/UI) in both themes; amber/green/red status verified AA against `--card` and `--background` in both themes.

## Component Anatomy (Claude's-discretion structure, fixed here for the executor)

**PlanCard (PAY-06, D-12)** — surface `--card`, padding `lg`, radius `--radius-lg`:
- Plan name (Heading), price (Display, `<bdi>` e.g. `9 USDT` / `3 USDT`) + cadence label ("/ mois", "/ 7 jours").
- Short benefit line + "payable en USDT (TRC-20)" note (consistent with P2 tarifs).
- Découverte card shows a "Offre découverte — une seule fois" badge; **hidden/disabled once consumed** (`plan='discovery'` already used → only standard shown, D-12). If a discovery period is active, standard card offers "Passer au standard" (early upgrade, no refund, D-12).
- Primary CTA "Choisir cette offre" → payment screen for that plan.

**PaymentPanel (PAY-01, PAY-02, D-01/D-03/D-05)** — single column `max-w-screen-sm`, blocks separated by `xl`:
1. **Network + address block** — "Réseau : TRC-20 (TRON)" prominent (D-01 "réseau en grand"); the shared address in a boxed tabular `<bdi>` string with a **1-tap copy button** (icon `Copy` → `Check` on success + sonner toast). QR (client-side svg) of the address, centered.
2. **Amount-due block** — the exact amount (Display, brand-blue, `<bdi>`, e.g. `9.02 USDT`) with its own copy button; a short note "Envoie EXACTEMENT ce montant — les centimes nous permettent d'identifier ton paiement." (explains the offset, D-05, reassuring). Optional offset-validity hint if the offset expires (Claude's discretion / planning flag).
3. **Hash submission form** (`form`+zod) — single text field "Hash de la transaction", inline validation (format/length), submit "J'ai payé — vérifier". Each submission is traced (D-04).
4. **Optional screenshot** — clearly marked "Capture d'écran (optionnel)"; zero friction if absent; never part of auto-verification (D-03). File picker, accepted types/size shown, removable preview.

**VerificationPolling (PAY-02/PAY-03, D-02)** — replaces the form on submit:
- Heading "Vérification en cours…" + reassuring sub-copy ("Cela prend généralement moins d'une minute. Ne ferme pas cette page.").
- **Stepped checklist** with live state per step (pending → done): e.g. « Transaction trouvée » → « Montant et destinataire vérifiés » → « Confirmations on-chain » → « Abonnement activé ». Each step: `Loader2` (active) / `Check` green (done) / muted (waiting).
- Polling via `@tanstack/react-query` (interval + timeout, Claude's discretion). On success → success state + auto-redirect/CTA to signals. On timeout → graceful "Toujours en cours" message with "Continuer en arrière-plan" (deferred-check fallback, D-02), never a hard error.

**VerificationFailure (PAY-04, D-04)** — `alert` (red, `CircleAlert`):
- **Precise reason** rendered from a typed error code → localized message, e.g. « Montant reçu 8 USDT, attendu 9.02 USDT », « Jeton non reconnu (ce n'est pas de l'USDT TRC-20) », « Transaction pas encore confirmée », « Ce hash a déjà été utilisé ». (`<bdi>` on all amounts/hashes.)
- Clear next step + "Soumettre un autre hash" returning to the form (re-submission traced). Trivial typos do NOT auto-route to the superadmin queue (D-04). Ambiguous over/under-payment → user sees a calm "Ton paiement est en cours de revue manuelle, nous revenons vers toi." (it lands in the admin queue, D-06/D-08).

**SubscriptionStatus + ExpiryBanner (PAY-05, D-09/D-10/D-11)**:
- Member-space status chip: "Actif jusqu'au {date}" (green) / "Expiré" (red) / "En attente de paiement" (blue), date via `Intl.DateTimeFormat`, `<bdi>`.
- **ExpiryBanner** (`alert`, amber) shown at J-3 / J-1 in the member space: « Ton abonnement expire dans {n} jours — renouvelle pour ne pas perdre l'accès. » + CTA "Renouveler" → payment flow (same parcours, D-11). In-app only, NO email (D-09). Non-dismissible while inside the J-3 window (it is actionable, not noise) — Claude's discretion on dismiss-per-session.
- Hard cut at `current_period_end` (D-10): once expired, the member sees the gated empty state + a "Renouveler" path (no grace period).

**AdminMembers (ADMIN-01, D-13/D-14)** — `(admin)` route group, mono-FR, `table`:
- Columns: email · statut (badge: Actif/Inactif/Expiré) · plan (discovery/standard) · date d'expiration · dernier paiement. (D-14)
- Filters: status select (actif/inactif/expiré) + email search input. (D-14)
- Row actions (`dropdown-menu`): "Activer / Prolonger", "Changer de plan", and destructive "Révoquer / Suspendre" (red, `alert-dialog` confirm). All write via service_role (D-13). No front write to `subscriptions`.

**AdminQueue (ADMIN-02, D-06/D-08)** — `table` in a "File de validation" tab:
- Rows = ambiguous payments: montant attendu / montant reçu (both `<bdi>`) · hash (link to TronScan, opens new tab, `rel="noopener noreferrer"`) · user · optional screenshot link · "À valider" amber badge.
- Actions per row: **"Activer"** (primary blue), **"Rejeter"** (destructive red → `alert-dialog` requiring a `textarea` **motif**), and **"Ajuster durée / plan"** (manual fix for edge cases, D-08) via a dialog. All service_role.
- Empty state = reassuring (the queue is intentionally usually empty).

## Interaction & States Contract

| Surface | States required |
|---------|------|
| PlanCard | rest · selected (accent border) · hover · focus-visible · discovery: available / consumed (hidden-or-disabled) · ≥44px CTA |
| Copy buttons (address/amount) | rest · hover (accent) · focus-visible · success (icon `Copy`→`Check` + toast, revert after ~2 s) · failure-to-copy fallback (select text) · ≥44px |
| QR | static, high-contrast, quiet zone; no interaction; offline-rendered; LTR; alt/aria label "QR de l'adresse de réception USDT TRC-20" |
| Hash form | empty · typing · invalid (inline error) · submitting (disabled + spinner on CTA) · submitted → polling · error (failure callout) |
| Screenshot field | empty (optional) · selected (preview + remove) · invalid type/size (inline message) · never blocks submit |
| VerificationPolling | active (stepped, spinner per step) · partial (some steps done) · success (auto-advance) · timeout (background fallback, never hard error) · network-lost (silent retry, keep reassuring copy) |
| VerificationFailure | visible reason (typed→localized) · re-submit path · ambiguous→calm manual-review message · all amounts/hashes `<bdi>` |
| ExpiryBanner | shown only J-3/J-1 · amber · actionable (« Renouveler ») · `prefers-reduced-motion` honored · RTL mirrored |
| SubscriptionStatus chip | active (green) · pending (blue) · expired/suspended (red) · always text + color |
| AdminMembers table | loading (skeleton rows) · loaded · empty (per filter) · filtering (status select + email search, URL-synced or local, Claude's discretion) · row-action menu open · action pending · action success/error (toast) |
| AdminQueue table | loading · loaded · empty (reassuring) · row actions (Activer / Rejeter+motif / Ajuster) · confirm dialogs · action pending/success/error (toast) · TronScan link `target=_blank rel=noopener noreferrer` |
| Destructive dialogs | `alert-dialog`: rest · focus-trapped · confirm disabled until motif present (Rejeter) · Esc/cancel · loading on confirm |

Responsive: mobile-first for the payer flow (most will pay from a phone — copy buttons and amount must be thumb-friendly, ≥44px, single column). Admin tables are desktop-first but wrap in a horizontal-scroll container on narrow screens (never clipped). All breakpoints validated in ar/RTL, both themes (member surfaces) and FR both themes (admin). `prefers-reduced-motion` honored for polling/step animations and banner transitions.

Accessibility: every status conveyed by **text + icon + color** (never color alone) — critical for the amber/green/red money states. Copy buttons announce success to assistive tech (`aria-live` on the toast region). The polling steps are an ordered list with `aria` state. Amounts/hashes/addresses are `<bdi>` and selectable. Focus management on form→polling→result transitions (move focus to the new heading). WCAG AA contrast both themes.
