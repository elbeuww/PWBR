<temporal_coherence_design>
DÉCISION DE CONCEPTION (load-bearing) — les 3 engines ancrent `computed_for_ts` DIFFÉREMMENT, vérifié dans le code :
- technical : `computed_for_ts = ltf.at(-1).ts` (dernière bougie LTF réelle en base ; day→H1, swing→H4)
- news      : `computed_for_ts = lastClosedCandleStart(now, LTF)` (théorique ; day→H1, swing→H4)
- fundamental : `computed_for_ts = latestMacroTs` (dernière observation FRED — granularité quotidienne/mensuelle, JAMAIS aligné sur une bougie)

⇒ Exiger un `computed_for_ts` IDENTIQUE entre les 3 produirait ZÉRO combined (fundamental ne s'aligne jamais sur l'heure). La cohérence se fait donc par **(instrument_id, style)** en prenant le snapshot **le plus récent de CHAQUE kind** (latest-par-kind via `computed_for_ts DESC`).

`computed_for_ts` du combined = celui du snapshot **technical** retenu (le plus granulaire, ancré sur une bougie réelle, anti-look-ahead — miroir technical/news ; jamais now(), jamais latestMacroTs). Cela rend la clé d'upsert (instrument_id, style, kind='combined', computed_for_ts) stable et avance d'un cran quand une nouvelle bougie LTF technical arrive → idempotence D-41 préservée.

`timeframe_set` du combined = celui du technical retenu (ex. 'H4/H1' day, 'D/H4' swing).
`partial` du combined = OU logique des `partial` des 3 sources (si technical partial → combined partial).

Triplet INCOMPLET (un kind absent pour instrument×style) → `stats.skipped++` + push errors avec msg normalisé (ex. `missing kinds: fundamental`), NE PAS combiner. Cohérence temporelle critique : on ne fabrique jamais un kind manquant ni un timestamp.
</temporal_coherence_design>
